# Mini Agent Runtime 规格说明（Spec）

> 已发布到本地 Issue Tracker。Tracker 约定见 `docs/agents/issue-tracker.md`，发布副本位于 `.scratch/mini-agent-runtime/spec.md`，标签映射见 `docs/agents/triage-labels.md`。内容综合已批准的词汇表、ADR-0001、ADR-0002、设计文档与测试计划，术语以词汇表为准。

## 问题陈述（Problem Statement）

想学习、演示或向他人解释一个 agent 的核心机制时，现成框架把 Turn/Step 循环、工具注册与调用、上下文组装与会话管理封装成黑盒：依赖重、难以逐行讲清楚，也很难按自己的假设改动验证。想从零实现一个能真实运行的版本，又容易在"最小"和"可用"之间失衡——要么只有 demo 级的单轮调用，要么很快膨胀成一个小框架。

本项目面向一名开发者在本机终端里的真实使用：需要模型能自主决定直接回答还是调用工具；多个会话互不干扰且可随时恢复；长对话不会因上下文失控而中断；出错时能解释、能恢复；整套行为可以脱离真实模型被稳定测试。同时，它也要能作为教学/演示素材，让每一步决策、每一次工具调用和每一条上下文都看得见。

## 解决方案（Solution）

一个运行在本机终端的单用户 Agent：用户用自然语言描述任务，Agent 依据工具的参数 schema 自主决定调用计算器、搜索、天气或待办工具，经过一个或多个 Step 后给出答复。

每个会话独立持久化，可用会话 id 跨进程恢复；不同窗口的会话彼此不可见。追问复用完整历史：换城市、省略主语、基于上一结果继续加工都能自然工作。长对话在达到预算时自动把较早的消息压缩为摘要，摘要放在系统消息中，不破坏消息配对。所有模型与工具调用写入结构化 Trace，终端可按需显示思考过程。

Runtime 完全自研，模型侧使用 DeepSeek 原生 function calling，零运行时依赖；测试通过脚本化假模型驱动，不访问网络、不需要密钥。

## 实现决策（Implementation Decisions）

### 模块与职责

- **模型适配（Model Adapter）**：Runtime 与模型提供方之间的唯一边界。输入为系统消息文本、Message 列表、Tool schema 列表、思考开关、输出上限与取消信号；输出为最终文本、思考内容、Tool Call 列表（每个调用的参数是 JSON 字符串）、结束原因与用量。
- **DeepSeek 适配器**：用内置 `fetch` 调用 OpenAI 兼容接口，负责请求映射、响应归一化、错误分类与取消；构造函数允许注入 `fetch` 实现，便于测试。
- **Turn/Step 运行时**：唯一理解 Turn 与 Step 语义的模块。负责追加用户消息、逐步调用模型、顺序执行工具批次、判断继续或结束、生成合成收尾消息。
- **工具注册表**：按名称注册工具；向模型暴露名称、描述与参数 schema；执行前校验参数；把异常统一转换为工具结果。
- **参数校验器**：自研 JSON Schema 子集校验，支持对象、字符串、数值、整数、布尔、数组、必填、枚举、范围、长度与 `additionalProperties: false`；遇到不支持的 schema 字段直接报错。
- **四个工具**：calculator（手写递归下降解析，禁止动态求值）、search（固定 fixture 的 mock）、weather（五个城市的 mock）、todo（会话级状态，Runtime 生成 id）。
- **Session 管理与存储**：创建、载入、保存、列表、切换；每个会话一个 JSON 文件；原子替换写入；跨进程锁；损坏检测与残缺配对修复。
- **Context 组装与压缩**：按固定顺序组装系统消息、历史消息与工具 schema；估算 token；在预算触发时把较旧消息摘要化并替换；注入摘要小节。
- **Trace 记录**：只追加的 JSONL，记录模型调用、工具调用、压缩、错误、取消、修复与轮次结束；密钥永不落盘。
- **CLI 与配置**：参数解析、REPL、会话内命令、中文文案；全部配置来自环境变量。

### 数据契约

**会话**包含：版本号、id、标题、创建与更新时间、模型名、思考模式、轮次序号、摘要、待办列表、消息列表。

**消息**包含：角色（system/user/assistant/tool）、文本内容、思考内容（assistant 专属，可为空）、Tool Call 列表（assistant 专属）、被调用的工具名与调用 id（tool 专属）、是否错误（tool 专属）、所属轮次与步数。

**待办**包含：id、内容、是否完成、创建时间。

**Trace 记录**的每行包含：时间、会话 id、轮次 id、步数、种类、耗时；种类为 llm、tool、compression、compression_fallback、error、cancelled、repair、turn_end，各自附带请求摘要、响应摘要、工具参数与结果、用量或错误信息。

**CLI 契约**：无参数新建会话；`--session` 恢复或新建；`--list` 列出会话；`--no-think` 对新建会话关闭思考；`--no-compress` 关闭压缩触发；`--verbose` 展示思考与工具细节；`--help` 帮助。会话内命令为 `/help`、`/exit`、`/new`、`/switch`、`/todos`。

**配置项**：API 密钥（必填）、基础地址（默认 DeepSeek 官方）、模型名（默认 `deepseek-flash`）、每轮步数上限（默认 8）、压缩预算（默认 32768）、压缩保留条数（默认 8）、新会话思考开关（默认开）、输出上限（默认 8192）、数据目录、锁过期时间（默认 10 分钟）。

### 关键行为决策

- **原生工具调用**（ADR-0001）：不使用自定义文本协议；Tool Call 参数按 JSON 字符串接收并解析，解析失败按工具错误处理。
- **思考模式**（ADR-0002）：新会话默认开启，使用低 reasoning effort；每条 assistant 消息持久化思考内容；带工具的请求必须逐条回传历史思考；思考模式与模型名在会话创建后不可切换，恢复会话沿用记录值；运行时合成的消息回传空思考，若真实 API 拒绝则回退为一行合成说明。
- **Turn 与 Step**：Turn 是原子单位，包含一次用户输入到最终答复；Step 是一次可用的模型响应加随后的一批工具调用；整批工具调用只计 1 个 Step；工具按顺序串行执行，单个失败不影响同批其他工具。
- **循环终止**：模型给出无工具调用的答复即正常结束；达到步数上限时追加合成收尾消息并返回已有进度；输出被截断时返回部分内容并提示；取消时结束当前 Turn；不可重试错误结束 Turn 并报错。
- **工具错误语义**：未知工具、参数不是合法 JSON、schema 校验失败、工具抛异常，一律作为 `is_error` 的 tool 消息回给模型，由模型决定纠正或告知用户，均计入 Step。
- **上下文组装**：系统消息（基础提示词加可选摘要小节）在前，历史 Message 依序在后，工具 schema 随请求携带；思考内容仅在思考模式进入上下文；工具结果单条超过 4000 字符截断。
- **压缩**：每次 Step 前检查估算 token 与消息条数；保留最近若干条原文；切点必须落在用户消息边界，绝不拆开 assistant 的 Tool Call 与对应工具结果；摘要由独立模型调用生成，输入包含旧摘要；摘要只放在系统消息中；失败时退化为丢弃最旧消息并保留最近条数；提供关闭开关。
- **会话隔离与持久化**：会话之间不共享任何状态；待办属于会话；会话 id 限定字符集以防路径穿越；写入采用临时文件加原子替换；跨进程使用锁文件，锁过期后自动清理；文件损坏时拒绝覆盖；载入时补齐缺失的工具结果，恢复消息配对合法性。
- **错误与重试**：网络错误、超时、429、5xx 在同一 Step 内最多重试两次，退避 1 秒、2 秒并尊重重试等待头；400、401、403、404 不重试；空响应重试一次；重试不增加 Step 计数；重试退避函数可注入，测试不真实等待。
- **安全**：计算器不使用动态求值，字符白名单加长度上限；系统提示词声明工具结果、搜索片段与摘要是数据而非指令；密钥仅来自环境变量且不写入任何文件；数据只落本地。
- **依赖**：零运行时依赖；开发依赖限于 TypeScript、tsx、vitest 与 Node 类型定义。
- **交付形态**：本地 CLI，不提供 Web 或 HTTP 服务；一次性响应，不做流式输出。

## 测试决策（Testing Decisions）

**什么算是好测试**：只验证外部行为——通过 Runtime 的公共入口观察响应、会话文件、Trace 与退出码，不断言私有函数调用；每个用例确定、可重复、无网络、无真实密钥；断言"模型收到了什么请求"与"用户最终看到什么"，而不是内部实现步骤。

**测试缝**（与已批准的测试计划一致，建议不再新增）：

1. **模型适配层（最高缝）**：用 FakeLLM 实现同一接口，按脚本驱动完整的 Turn/Step 循环，并记录每个请求，用于断言历史完整性、思考回传、压缩后的消息与摘要位置。
2. **`fetch` 注入**：适配器接受注入的 HTTP 实现，用于验证请求映射、响应归一化、错误分类、重试等待头与取消，不访问网络。
3. **数据目录注入**：Session 存储、锁与恢复在临时目录的真实文件系统上测试，不 mock 文件系统；两个会话的隔离用两个独立管理器验证。
4. **CLI 命令处理**：参数解析与会话内命令作为可调用函数测试；端到端可用子进程加临时数据目录，模型侧仍用 FakeLLM。

**被测模块**：Turn/Step 循环、Context 组装与压缩、工具注册表与校验器、四个工具、Session 存储与锁、DeepSeek 适配器映射、CLI 参数与命令解析。

**既有先例**：全新项目，无既有测试可参照；FakeLLM 加注入式 `fetch` 将成为后续测试的基准模式。用例分为 A–E 五组（循环、工具、会话、上下文与追问、错误与 Trace）进入 CI，F 组为真实模型手动冒烟。

**覆盖要求**：循环四步与终止条件；工具注册、参数校验与各类错误；会话隔离、恢复、锁与损坏修复；追问三类语义；压缩触发、切点、回退与二次合并；思考回传与摘要位置；重试与 Trace 完整性。

## 范围之外（Out of Scope）

- Web UI、HTTP 服务、多用户与鉴权。
- 流式输出。
- RAG、文档检索工具与向量数据库。
- 复杂压缩（分层记忆、向量摘要、跨会话记忆）。
- 工具沙箱与工具并行执行。
- 中途打断并续跑同一个 Turn。
- 真实模型的输出质量评测、性能与压力测试、UI 自动化。
- 多模型并行、模型热切换。
