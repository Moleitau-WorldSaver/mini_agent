# 领域文档

工程技能在探索代码库时应如何阅读本仓库的领域文档。

## 探索前先读

- 仓库根目录的 `GLOSSARY.md`；若存在 `GLOSSARY-MAP.md`，则按它指向的各上下文 `GLOSSARY.md` 阅读相关部分。
- `docs/adr/`：阅读与当前工作区域相关的 ADR。

这些文件不存在时**静默继续**：不要提示缺失，也不要主动建议创建。`/domain-modeling` 技能会在术语或决策真正落地时懒创建。

## 文件结构

本仓库为单上下文：根目录 `GLOSSARY.md` + `docs/adr/`。

## 使用词汇表

输出中出现领域概念时（issue 标题、重构提案、假设、测试名），使用 `GLOSSARY.md` 定义的词，不要漂移到它明确回避的同义词。

需要的概念不在词汇表中时，这是一个信号：要么你在发明项目不用的语言（重新考虑），要么确有缺口（交给 `/domain-modeling` 记录）。

## 标出 ADR 冲突

输出与现有 ADR 矛盾时，明确指出来，不要静默覆盖：

> _与 ADR-0007（事件溯源的订单）矛盾，但值得重开，因为……_
